# XAI-Guard: Three-Pillar Evaluation Framework

To objectively and reproducibly determine which Artificial Intelligence model best serves a modern Security Operations Centre (SOC), XAI-Guard evaluates all architectures against a strict Three-Pillar Evaluation Framework. Models are assessed not solely on predictive capability, but on the reliability of their explanations and their operational viability at the edge.

---

## Pillar 1: Prediction Performance
The core capacity of the model to distinguish malicious adversarial traffic from benign network behavior across highly imbalanced datasets.

### Primary Global Metrics
- **F1-Macro:** The harmonic mean of precision and recall, calculated independently for each class and unweighted by class frequency. This is our primary indicator of model performance on minority attack classes (e.g., Infiltration).
- **ROC-AUC (Macro OvR):** The Area Under the Receiver Operating Characteristic Curve, computed using a One-vs-Rest (OvR) strategy to evaluate the model's probabilistic ranking ability across all attack types.
- **PR-AUC (Macro):** Area Under the Precision-Recall Curve, critical for datasets with extreme class imbalance like CICIDS-2017.
- **Accuracy, Precision (Macro), Recall (Macro):** Tracked as secondary context metrics.

### Class-Level Granular Metrics
To ensure the model does not merely overfit to high-frequency attacks like DDoS, we explicitly track the F1-Score for every specific class in the unified taxonomy:
1. `F1_DDOS`
2. `F1_PORT_SCAN`
3. `F1_BRUTE_FORCE`
4. `F1_BOTNET`
5. `F1_WEB_ATTACK`
6. `F1_INFILTRATION`
7. `F1_NORMAL`

## Pillar 2: Explainability Quality
A mathematically rigorous assessment of the reliability, stability, and utility of the explanations generated by the eXplainable AI (XAI) subsystem (SHAP, LIME, Attention Rollout).

### 2.1. SHAP Stability Score ($S_{shap}$)
Explainability methods must be deterministic and stable against minor perturbations. The stability of SHAP feature contributions is measured using the Coefficient of Variation ($CV$) across $n=10$ identical explanation runs for the same prediction.
$$ S_{shap} = 1 - \frac{\sigma_{shap}}{\mu_{shap}} $$
*A higher score indicates the XAI method yields consistent reasoning over multiple evaluations.*

### 2.2. XAI Rank Correlation 
To ensure consensus among explanation methods, we calculate the Spearman rank-order correlation coefficient ($\rho$) between the top-5 most important features identified by different XAI paradigms on the same prediction:
- **LIME-SHAP Correlation:** Agreement between local surrogate models and Shapley values.
- **Attention-SHAP Correlation:** (Specific to Transformer architectures) Agreement between inherent self-attention weights and post-hoc SHAP values.

### 2.3. Analyst Utility Composite Score ($U_{analyst}$)
A heuristic evaluating how actionable the explanation is to a human Tier-1 SOC analyst, based on 5 sub-metrics (scored 0.0 to 1.0):
1. **Sparsity:** Penalizes explanations that distribute importance across too many features.
2. **Feature Comprehensibility:** Rewards explanations that highly rank easily understandable network features (e.g., `Destination Port`) over abstract mathematical derivatives.
3. **Temporal Relevance:** Evaluates if the explanation highlights the correct chronological packets in a sequence-based attack.
4. **Contrastive Clarity:** The delta between the highest contributing malicious feature and the highest contributing benign feature.
5. **Compute Latency:** Explanation generation time (must be < 500ms).

---

## Pillar 3: Operational Fitness
An evaluation of the model's hardware efficiency, inference cost, and deployment viability for CPU-only edge nodes.

### Operational Metrics
- **Inference Latency ($L_{P50}, L_{P95}, L_{P99}$):** Measured in milliseconds (ms) under a sustained load of 1,000 events per second. The $P99$ latency is a hard gating constraint; any model exceeding a $P99$ of 100ms is disqualified from production Champion status.
- **Throughput:** Processed events per second per CPU core.
- **Peak Memory Footprint ($M_{RSS}$):** Resident Set Size (RSS) memory in MB utilized during sustained inference.
- **Training Cost ($C_{train}$):** Total GPU-hours required for the model to converge.
- **Artifact Size:** On-disk size of the serialized model weights (MB).

---

## The Composite Deployment Score (CDS)
To automate the Champion/Challenger promotion cycle in our MLOps pipeline, we distill the most critical metrics from Pillars 1 and 3 into a single, scalar heuristic: the **Composite Deployment Score (CDS)**. 

### Normalization Procedure
Because F1, Latency, and Memory are on entirely different scales, they are min-max normalized ($norm(x)$) between $0.0$ and $1.0$ relative to the baseline Logistic Regression model established during Phase 37. Note that for Latency and Memory, we normalize their *inverses*, as lower values are superior.

### The Formula
$$ CDS = 0.40 \cdot norm(F1_{macro}) + 0.35 \cdot norm\left(\frac{1}{L_{P99}}\right) + 0.25 \cdot norm\left(\frac{1}{M_{RSS}}\right) $$

*Any Challenger model attempting to depose the reigning production Champion must achieve a strictly higher CDS while independently passing the strict $P99 \le 100ms$ operational gate.*
