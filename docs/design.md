# Swiss + Minimalism UI Design Guideline

Design and maintain the entire application using a **Swiss / International Typographic Style combined with Modern Minimalism**.

This is a **design philosophy and visual guideline**, not a fixed component specification.

Do not introduce arbitrary visual decisions that conflict with this design language.

---

## 1. Core Philosophy

The entire product must follow these principles:

* clarity over decoration
* hierarchy over visual complexity
* functionality over ornamentation
* typography over unnecessary graphics
* structure over randomness
* consistency over novelty
* whitespace over clutter
* information readability over visual effects
* purposeful design over decorative design

Every UI decision should answer:

> Does this improve clarity, usability, hierarchy, or understanding?

If the answer is no, remove or simplify it.

---

## 2. Swiss Design Principles

Use the principles of the Swiss / International Typographic Style throughout the application.

The interface should be based on:

* structured composition
* systematic alignment
* grid-based thinking
* strong typography
* visual hierarchy
* consistency
* balance
* controlled asymmetry
* intentional whitespace
* objective information presentation

Elements should appear deliberately placed rather than individually decorated.

Maintain a clear relationship between:

* navigation
* headings
* content
* data
* actions
* supporting information

The user should be able to understand the structure of a page immediately.

---

## 3. Minimalist Principles

Use minimalism as an editing discipline.

Do not interpret minimalism as simply making the interface empty.

Instead:

> Keep everything necessary and remove everything unnecessary.

Avoid unnecessary:

* decorative graphics
* visual effects
* excessive icons
* excessive badges
* excessive labels
* unnecessary containers
* redundant information
* repetitive sections
* decorative animations
* visual noise

Every element must have a reason to exist.

---

## 4. Information Hierarchy

Information hierarchy is one of the most important principles of the system.

Clearly distinguish between:

* primary information
* secondary information
* supporting information
* metadata
* actions
* system status

Users should immediately understand:

1. Where they are
2. What they are looking at
3. What is important
4. What requires attention
5. What action they can take

Do not create visual hierarchy simply through decoration.

Prefer hierarchy through:

* typography
* positioning
* grouping
* alignment
* whitespace
* contrast
* scale
* repetition

---

## 5. Grid and Alignment

Think in terms of a consistent underlying grid.

Major elements should share common alignment points.

Avoid arbitrary positioning.

Maintain alignment between:

* page headers
* navigation
* content sections
* tables
* charts
* forms
* actions
* supporting information

When using asymmetric layouts, the asymmetry must feel intentional and structured.

Never introduce asymmetry simply to make the design look different.

---

## 6. Typography as a Design Tool

Typography should be treated as one of the primary visual elements of the application.

Use typography to communicate:

* hierarchy
* importance
* grouping
* context
* status
* relationships between information

Avoid relying on decorative UI elements to create hierarchy when typography can communicate it more effectively.

Headings should be purposeful.

Body content should remain highly readable.

Metadata should remain visually subordinate.

Actions should remain immediately understandable.

Do not use typography merely for visual styling.

Typography must serve information architecture.

---

## 7. Whitespace

Whitespace is an active part of the design system.

Use whitespace to:

* separate concepts
* establish hierarchy
* improve readability
* create visual rhythm
* reduce cognitive load
* distinguish sections

Do not fill empty space simply because it exists.

At the same time, do not create excessive empty space that makes information difficult to scan.

Whitespace must be intentional.

---

## 8. Components

All components must follow the same Swiss + Minimalist philosophy.

Components should be:

* predictable
* restrained
* functional
* consistent
* readable
* reusable

Do not make every component visually distinctive.

Buttons should clearly communicate actions.

Inputs should clearly communicate expected input.

Tables should prioritize data readability.

Dialogs should prioritize the task being performed.

Navigation should prioritize orientation.

Cards or containers should only be introduced when they provide meaningful grouping or separation.

Do not turn every piece of content into a separate visual box.

---

## 9. Layout Philosophy

Do not design every page independently.

The entire application must feel like one coherent product.

Different pages may have different information structures, but they must share the same underlying visual language.

Maintain consistency across:

* navigation
* page structure
* section organization
* typography
* alignment
* interaction patterns
* content hierarchy
* component behavior

A user moving from one part of the application to another should immediately recognize that they are still inside the same system.

---

## 10. Data-Heavy Interfaces

This project contains complex AI, cybersecurity, and analytical information.

Therefore, prioritize information density without creating visual clutter.

For:

* tables
* charts
* metrics
* model comparisons
* threat analysis
* risk analysis
* experiment results
* explainability information

focus on:

* scanability
* grouping
* hierarchy
* consistency
* analytical clarity

Do not decorate analytical information unnecessarily.

The visualization must help users understand the data rather than compete with it.

## 11. Enterprise UX

The interface must feel appropriate for a serious enterprise environment.

Avoid visual trends that make the product feel like:

* a casual consumer application
* a gaming interface
* a marketing template
* a crypto dashboard

The visual language should communicate:

* precision

* intelligence
* trust

The interface should feel mature and intentional.

For model-related information, prioritize:

* evidence
* comparison
* transparency
* reproducibility
* interpretation
* relationships between models
* experiment context

## 13. Explainable AI

Explainability is a first-class part of the product.

The interface should communicate explanations clearly rather than hiding them behind decorative UI.

When presenting model explanations:

* establish the prediction first
* provide supporting evidence

The user should be able to follow the reasoning path.

The design must support analytical thinking.

## 14. Cybersecurity Context

Cybersecurity information often contains different levels of urgency and importance.

The UI should communicate these distinctions clearly and consistently.

Do not rely on visual decoration to make threats appear "cybersecurity-like."

Avoid unnecessary:

* neon aesthetics
* hacker imagery
* futuristic effects
* excessive glowing elements
* cyberpunk decoration
* animated backgrounds

The application should feel like a professional security intelligence platform rather than a fictional hacker interface.

## 15. Visual Restraint

When deciding between two design approaches, prefer the simpler one if both communicate the same information.

Avoid:

* excessive gradients
* excessive shadows
* excessive rounded containers
* excessive animation
* excessive iconography
* excessive illustrations
* excessive visual effects
* unnecessary decorative patterns

The design should feel refined because it is carefully edited, not because it contains many visual effects.

Do not introduce a new visual treatment for every page.

Do not create:

* one style for the dashboard
* another style for the model page

Everything belongs to the same design system.

New components should inherit the established visual language.

## 17. Responsive Design Philosophy

Responsive design must preserve the Swiss + Minimalist principles.

On smaller screens:

* simplify secondary information
* prioritize important content
* reorganize complex layouts
* preserve readability
* maintain clear navigation
* reduce unnecessary visual elements

Responsive behavior should be intentional rather than automatic.

## 18. Accessibility

Minimalism must never compromise accessibility.

The interface must remain:

* readable
* understandable
* keyboard accessible
* screen-reader friendly
* visually distinguishable
* usable without relying on color alone

Clarity always takes priority.

## DS-2. Typography System

### Typeface Rationale

- **Interface font:** Inter — Optimized for screen readability at small sizes. Clean, neutral, Swiss in character.
- **Monospace font:** JetBrains Mono — For ML metrics, model IDs, API endpoints, code, confidence scores.
- **NO display fonts**, slab serifs, hand-written, or decorative typefaces.

### Scale Application Rules

| Level | Size / Weight | Use Case |
|-------|--------------|----------|
| `label-xs` | 11px / 500 | Column headers, metadata labels, badge text |
| `label-sm` | 12px / 500 | Table sub-headers, section labels, status text |
| `body-sm` | 12px / 400 | Supporting text, descriptions, tooltips |
| `body` | 14px / 400 | **Primary reading body text** — all table cells, form content |
| `body-md` | 14px / 500 | Emphasized body — first column in tables, key metrics |
| `heading-sm` | 16px / 600 | Section headings, panel titles, card headings |
| `heading-md` | 20px / 600 | Page-level section headings |
| `heading-lg` | 24px / 700 | Page titles (used once per page) |
| `display` | 30px / 700 | Dashboard KPI numbers, large metric values |
| `mono-sm` | 12px mono | Hash IDs, timestamps, confidence scores, code |
| `mono-base` | 13px mono | Model metrics in tables, SHAP values, probabilities |

### Typography Rules
- **Line height:** 1.5× for body, 1.2× for headings
- **Letter spacing:** Tight (−0.01 to −0.03em) for headings; 0 for body; +0.02em for ALL-CAPS labels
- **Text color for data:** `neutral-900` primary, `neutral-600` secondary, `neutral-400` tertiary/placeholder
- **Never center-align** body text or table cells. Left-align all textual content. Right-align numeric columns only.
- **Numeric columns:** Always use `font-mono`, right-align, tabular-nums (`font-variant-numeric: tabular-nums`)

          {/* Swiss chart style: no background, minimal grid */}

            axisLine={false}

          <ReferenceLine
            x={0}
            stroke="#999999"
            strokeWidth={1}
          />
          <ReferenceLine
            x={baseValue}

            strokeDasharray="3 3"
            label={{ value: 'Base', position: 'top', fontSize: 10, fill: '#999999' }}
          />
          <Tooltip
            contentStyle={{

              fontSize: '12px',

            formatter={(value: number) => [value.toFixed(4), 'SHAP']}
          />
          <Bar dataKey="value" radius={0} maxBarSize={20}>

                key={entry.feature}
                fill={entry.value > 0 ? '#B91C1C' : '#1D4ED8'}
                opacity={0.85}
              />
            ))}
          </Bar>

      </ResponsiveContainer>

          <span className="inline-block w-3 h-2 bg-normal opacity-85" />

        </span>

  )
}

## SH-7. shadcn/ui Component Audit — What to Use, Avoid, Override

| Component | Use As-Is | Override Required | Do Not Use |
|-----------|-----------|-------------------|------------|
| `Button` | No | Yes — remove rounded-md, adjust variants | — |
| `Badge` | No | Yes — remove rounded-full, add severity variants | `rounded-full` |
| `Card` | No | Yes — remove rounded-lg shadow-sm | As generic container |
| `Table` | Partially | Yes — TableHead font, TableRow hover | — |
| `Input` | No | Yes — remove ring on focus | — |
| `Select` | Yes | Mild — content radius | — |
| `Dialog` | No | Yes — remove rounded-lg, tighten shadow | Full-screen dialogs |
| `Sheet` | Yes | Width, shadow-md only | — |
| `Tabs` | No | Yes — underline style, remove pill | Pill/segment tabs |
| `Tooltip` | No | Yes — white bg, 1px border | Black inverted tooltip |
| `Separator` | Yes | Color only | — |
| `Skeleton` | No | Yes — remove animate-pulse | — |
| `Progress` | No | Yes — remove rounded-full | — |
| `Switch` | No | Yes — smaller size | — |
| `Popover` | Yes | Content radius | — |
| `DropdownMenu` | Yes | Content radius, item style | — |
| `AlertDialog` | Yes | — | For non-destructive confirmations |
| `Accordion` | Yes | Border, no chevron animation | — |
| `Calendar` | Yes | — | Decorative date displays |
| `Command` | Yes | — | — |
| `Combobox` | Yes | — | — |
| `DataTable` | Build custom | TanStack Table + shadcn Table | — |
